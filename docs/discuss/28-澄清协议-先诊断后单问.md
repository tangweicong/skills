## 用户输入（本轮）

> 用户提供 prompt：「请先不要回答我的问题。在给出答案之前，请先完成以下分析：1、指出我在这个问题中没有明确说出、但已经默认成立的假设；2、告诉我还缺少哪些关键信息，以及这些信息可能如何改变你的答案；3、指出人们在处理这类问题时最常犯的一个错误。然后，请只向我提出一个最关键的问题……等我回答以后，你再给出最终输出。」
>
> 用户理由：这段 prompt 能避免人和 AI 双方的「理所当然」，把隐式信息显化，避免静默决定，尽可能同步人和 AI 双方的认知。

### 已查证事实

- **F1 · 一次一问（coaching 纪律）**：The Coaching Habit 的核心 = 每次只问一个问题、等答、再继续；理由 = 人一次只能真正思考一个问题，多问会让答案浅化且压垮低带宽的回答者 [Stanford](https://searchworks.stanford.edu/view/14890127) / [Clarity Circle](https://www.theclaritycircle.com/blog/what-makes-a-good-coaching-question)。
- **F2 · Assumption Surfacing（假设显式化）**：决策前的标准技术——显式列出「我们正在默认什么」，逐个检验；与用户痛点「双方的理所当然」精确对应 [PSU creativity](https://creativity.psu.edu/project/assumption-surfacing/)。
- **F3 · 既有机制盘点（内部事实）**：苏格拉底六问 = **问法菜单**（AI 挑 3–5 个点，非固定协议）；盲点双问（ORD-37）= **就绪门槛一次性**；轻量框定 = 分析层内部查证清单（不面向用户交互）；三分离/维度表 = 讨论**产出层**的显式化；teach-back = GATE 拍板点认知同步。

### 推理（非事实、非待验证）

- **推理 · Bungay Stanier（coaching）**：该 prompt 第 4 步「只问一个最关键的问题」是本方案**最独特的增量**——既有机制的显式化都在文档层（三分离/维度表）或门槛层（盲点双问），唯独没有「**每次新议题首次交互的节奏协议**」；一次一问同时服务三件事：防静默决定（AI 不能自己把缺口填了）、匹配人信道带宽（用户惰性痛点）、倒逼 AI 选出真关键问题；依据 [The Coaching Habit](https://searchworks.stanford.edu/view/14890127) 的 one-question discipline。
- **推理 · Assumption Surfacing（决策科学）**：组件 1（指出默认假设）是假设显式化的交互版——放在「回答之前」的位置使其成为**强制步骤**而非可选检查；这正是「理所当然」的解法：不是人想不起来问，而是协议规定必须先问；依据 [PSU creativity](https://creativity.psu.edu/project/assumption-surfacing/)。
- **推理 · ORD-38（反套话四机制）**：组件 3（最常犯的错误）是**套话风险最高**的一步（「人们常犯的错误是沟通不畅」式泛话）→ 融入时必须挂 ORD-38 具体性约束（挂靠问题类型 + 写中招后果），否则它自己就会变成用户讨厌的「谁都能套用的通用建议」；依据 ORD-38 四机制（DECISIONS）。

## 讨论

### 1. 逐条评估：四个组件 vs 既有机制

| prompt 组件 | 既有机制重合 | 真增量 |
|-------------|-------------|--------|
| ① 指出默认假设 | 苏格拉底六问「追假设」（可选）、维度表（产出层） | **固定步骤化**（回答前的强制动作）+ 面向用户交互 |
| ② 缺哪些信息 + 如何改变答案 | 轻量框定（分析层内部，不面向用户）、盲点双问（门槛一次性） | **「若 X 为真则答案偏向 Y」的显式敏感性说明** + 每次新议题 |
| ③ 最常见错误 | proj-experts 失败模式（skill 自用） | 面向**用户问题域**的错误预警（但套话风险最高，见推理 3） |
| ④ 只问一个最关键的问题 + 等答 | — | **无既有对应物**；一次一问的交互节奏协议是本方案核心增量（F1） |

**结论**：四个组件各自有亲属，但「**固定协议 + 单问等答节奏 + 面向交互层**」这个组合是新的——且与用户四痛点（模糊性/静默决定/惰性带宽/认知同步）一一对应。**值得融入，位置在苏格拉底澄清轮与每轮新议题的首次回应**。

### 2. 融入设计（候选 ORD-46）

**澄清协议（先诊断后单问）**——模糊想法/新议题的**首次回应**：

1. **先诊断后回答**（3 步，固定顺序）：
   a. 指出用户**未明说但已默认的假设**（≥1 条，挂靠具体对象；Assumption Surfacing）；
   b. 列出**还缺的关键信息** + 各自如何改变结论（「若 X 为真 → 答案偏向 Y」）；
   c. 指出**这类问题最常见的 1 个错误**（挂靠该问题类型 + 写中招后果——ORD-38 反套话约束，泛话=不合格）。
2. **单问等答**：诊断后只提**一个**最关键的问题，等用户回答后再给完整输出（一次一问 · F1）。
3. **触发条件**：模糊想法 / 新议题首次回应**必用**；明确指令、执行请求、GATE 确认等**跳过**（节奏纪律，对齐 ORD-44「只在拍板点用」精神——协议只在澄清点用）。
4. **与既有机制的关系**：苏格拉底六问 = 诊断后的**追问菜单**（保留不动）；盲点双问 = 就绪门槛一次性（不动）；本协议 = 每次新议题的**首次交互形态**。

### 3. 风险与路径（建设性前置）

| 风险 | 路径 |
|------|------|
| 每次回复都 3 诊断 → 仪式化、拖慢明确请求 | 触发条件收窄（§2 第 3 条）：只对新议题首次回应；后续回合直接讨论 |
| 组件 ③ 套话化 | ORD-38 约束写进协议：挂问题类型 + 中招后果，无对象泛话=不合格；连续 3 次套话 → 撤销组件 ③ |
| 一次一问退化为一次多问 | 协议明文「只提一个」；违反=失败模式（写入 SKILL.md） |
| 协议被 AI 无视（EXP-14 教训：纪律靠落点） | 落点进 proj-shape SKILL.md（协议正文）+ 失败模式一条 |
