### 已查证事实

- **F1 · AgileEVM 先例**：EV = 已完成 story points，只计完成不计部分（0/100 同构）；AgileEVM 被用于 release/iteration 级预测 [ACM AGILE 2006](https://dl.acm.org/doi/10.1109/AGILE.2006.15)。
- **F2 · 既有模板现状（内部事实）**：plan-template 任务表无权重列；dispatch-manifest `validation criteria` 字段（ORD-21）已要求「一行命令可判定」——**挣得标准（earn against criteria）已在，缺的只是记账层**。
- **F3/F4/F9（复用 r22）**：EV=对标准挣得非自报；%complete 主观性批判；指标被博弈/学生综合征（URL 见 `22-基于系统6论深度改造.md` §已查证事实）。

### 推理（非事实、非待验证）

- **推理 · 模拟推理 · Fleming & Koppelman（EVM）**：0/100 挣得规则是 EVM 中主观性最低的挣得方式；迁移到 AI 工作的关键 = 挣得标准必须**机器可判**——本项目恰好已有（ORD-21 validation criteria + ORD-22 三类机检），故 I-1 本质是「**给既有 gate 结果补账本**」而非引入新测量；依据 [Wits EVM PDF](https://wiredspace.wits.ac.za/server/api/core/bitstreams/5a124b51-4b6d-48e5-a443-d002a76c61a5/content) 的挣得规则 + r22 F3/F4。
- **推理 · 模拟推理 · Goldratt（TOC）**：任何进度指标都会被博弈；0/100 + 机检判据把博弈面压到「标准写得松」（spec gaming 面），该面由 ORD-22 负向断言强度兜底——记账层**不新增**博弈入口；依据 [Praxis critical chain](https://www.praxisframework.org/en/library/critical-chain) 的局部测量批判 + r22 F6/F9。
- **推理 · 模拟推理 · Wiener（控制论）**：r22 指出当前负反馈时延=整个实现周期；0/100 记账把「假完成」信号从**最终验收**提前到**每个任务的 validation 时刻**——不改变流程，只把已发生的 gate 结果变成 phase 内可见的偏差仪表，等于给大时延反馈环加相位提前；依据 [Good Regulator Theorem](https://en.wikipedia.org/wiki/Good_regulator_theorem) + r22 推理节控制论条。

## 讨论

### 1. 设计三原则

1. **命名+接线，不新增机制**（ORD-27/31 纪律）：0/100 挣得 = 给 ORD-21/22 的既有 validation 结果加「账本语义」，不新增流程、不新增 artifact、不新增人的负担。
2. **二值入账，禁 %complete**（F4）：EV 只允许 0 或 PV 两个值——「承诺完成」在账本上无表达空间。
3. **指标只报警不入激励**（F9）：EV% 是偏差仪表，触发既有 escalate/circuit breaker；不作考核口径、不作奖励函数。

### 2. 设计（候选 ORD-41）

- **PV 列**：`phase-NN/plan.md` 主任务表加「PV」列 = 任务计划权重；**默认均权（全部 1）**，粒度悬殊时允许 1–3 加权（planner 定，U2 观察后再决定是否常态化）。
- **EV = 派生量**：任务行的 validation criteria 全部通过（= 状态勾 ✓）→ EV=PV；未过 → EV=0。**不设独立 EV 列**——「✓」就是 0/100 的唯一判据（F2：标准已在 manifest）。
- **进度仪表**：phase 执行中 EV% = Σ已✓PV / ΣPV（= 验收通过任务加权占比）；**替代口头「承诺完成」**为唯一进度口径。
- **偏差接线**（全部既有）：EV=0 的任务 → 走该任务 `iteration budget` 重试路径（ORD-21）；phase 级累计失败 >3 → circuit breaker abort（dispatch-manifest §iteration 总策略，原样不动）。
- **AC 成本侧 v1 不强制**：token 成本按既有惯例记录（EXP-04/EXP-12 载体法），不在 plan.md 加 AC 列（YAGNI；完整 SPI/CPI 留 EXP-12 步2 载体顺便验证）。

### 3. 账本位置的三个选项

| 选项 | 内容 | 判定 |
|------|------|------|
| A（选） | plan 任务表加 PV 列；acceptance 加「挣得进度」节（EV% + 未挣得任务清单） | 最小面；proj-run 直接在既有文件读/写；EV 派生无冗余 |
| B | 只放 acceptance.md 阶段级 | 粒度粗（阶段级非任务级），损失「每任务 validation 时刻」的提前量 |
| C | 独立 earned-value.md 新 artifact | 新文件=新维护负担（Haken 熵警告）；YAGNI |

### 4. 反博弈自查

0/100 记账的博弈面 = 「把 validation criteria 写松」（F6 spec gaming）。该面**已由 ORD-22 兜底**（behavioral 类 = 负向断言如 `rg -c "model:" = 0`；criteria 必须一行命令可判）。记账层不新增博弈入口（选项 A 无新字段可博弈——PV 权重是唯一新输入，故默认均权）。**结论：本设计对 spec gaming 的暴露面为零增量**。
