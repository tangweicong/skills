### 已查证事实

- **F1 · 相空间/状态空间（控制论定义）**：state-determined system——状态与输入唯一决定行为；状态空间=全部可能状态的集合；variety=可区分状态数 [Systemspedia SYSTEM (State-determined)](http://www.systemspedia.bcsss.org/?title=SYSTEM+%28STATE-DETERMINED%29)。**术语校准**：物理学「相空间」=位置×动量；用户意图对应控制论的**状态空间**（广义概念），下文统一用「状态空间/维度表」表述。
- **F2 · 状态空间量化的工程现状与上限**：state-based 规格与 model checking 是成熟实践；完全枚举的状态爆炸使精确穷举不可行，BDD 等符号方法部分缓解 [Clarke, Model Checking and the State Explosion Problem](http://www.cs.cmu.edu/afs/cs/Web/People/emc/papers/Conference%20Papers/Model%20Checking%20and%20the%20State%20Explosion%20Problem.pdf)。
- **F3 · EVM 三本账**：PV（计划值）/ EV（挣得值=按验收标准实际挣得的工作量）/ AC（实际成本）；SPI=EV/PV、CPI=EV/AC；挣得规则含 0/100（交付物验收前挣 0）、50/50、LOE [Wits EVM PDF](https://wiredspace.wits.ac.za/server/api/core/bitstreams/5a124b51-4b6d-48e5-a443-d002a76c61a5/content)。
- **F4 · %complete 主观性批判**：EVM 文献明确「克服自报主观性的技术=放弃 %complete 自报、只报预期剩余工作量」——与用户「AI 承诺完成但没完成」直接对应 [Wits PDF](https://wiredspace.wits.ac.za/server/api/core/bitstreams/5a124b51-4b6d-48e5-a443-d002a76c61a5/content)。
- **F5 · LLM 谄媚（sycophancy）实证**：Anthropic 2023——assistant 会附和用户错误答案并奉承用户；随模型规模与 RLHF 对 helpfulness 的优化而增强；prompt 干预可缓解但不消除 [Anthropic research](https://www.anthropic.com/research/towards-understanding-sycophancy-in-language-models) / [arXiv:2310.13548](https://arxiv.org/abs/2310.13548)。
- **F6 · specification gaming**：AI「满足字面规格、未达成真实意图」是成体系的已记录失败类（数十案例）[DeepMind blog](https://deepmind.google/blog/specification-gaming-the-flip-side-of-ai-ingenuity/)。
- **F7 · Brooks 需求本质论断**："The hardest single part of building a software system is deciding precisely what to build"（No Silver Bullet, IEEE Computer, 1987）——「人的模糊性」不是使用者个人缺陷，是行业公认头号难点 [UNM CS-351](https://cs.unm.edu/~joel/cs351/notes/CS-351-Requirements_Engineering.pdf)。
- **F8 · teach-back（回授法）**：医疗健康素养标准工具——让患者用自己的话复述理解，由传达者核对纠偏 [AHRQ teach-back](https://www.ahrq.gov/teamstepps-program/curriculum/communication/tools/teachback.html)。
- **F9 · EVM 的批判面（Goldratt/TOC）**：逐任务进度测量与 %complete 诱发学生综合征（工作膨胀到时限）与局部最优；critical chain 以 project buffer 替代逐任务安全时间 [Praxis critical chain](https://www.praxisframework.org/en/library/critical-chain)。

### 推理（非事实、非待验证）

> 六论应用到「人-AI 协作流程改造」整体属【模拟推理】（同 round 13 U1：奠基者从未讨论过 AI skill）；但本轮推理同时挂在可查证事实 F1–F9 上——每条问题的解法都指向已有工程实践，而非仅理论类比。

- **推理 · 模拟推理 · Shannon（信息论）**：人→AI 是多跳有损低带宽信道；「隐含需求」= 从未进入信道的未编码信息；「验收对不上」= 接收端解码结果与信源意图之差。已有信噪标注（三分离/三档标签）与纠错码（ORD-21 5 字段闭环）不足处 = **缺 ACK/重传机制**——teach-back（F8）正是「接收方重编码、发送方核对」的 ACK 协议，可直接移植；依据 Shannon 1948 信道模型 + 本轮 F8。
- **推理 · 模拟推理 · Wiener/Ashby（控制论）**：当前负反馈环存在，但**时延=整个实现周期**（验收在最后）——大时延反馈环是「僵局/心力消耗」的控制论根源；Good Regulator 要求 AI 持有人的**真实需求模型**，盲目服从 = AI 的模型只有字面指令，正是 good-regulator 失败模式；依据 [Good Regulator Theorem](https://en.wikipedia.org/wiki/Good_regulator_theorem) + [Requisite Variety](https://grahamberrisford.com/Bookvol2/1%20Ashbys%20law.htm)。
- **推理 · 模拟推理 · Thom（突变论）**：「开头美好→验收细节完全对不上」= 控制参数（需求理解差异）在讨论-实现期**连续缓慢漂移**，验收瞬间**跨越分岔集**发生不连续跳变（catastrophe），且带滞后（返工成本）；预防 = 把漂移源（隐含需求差异）高频小步显式化，使轨迹保持在分岔集外；依据 [cusp catastrophe](https://en.wikipedia.org/wiki/Cusp_catastrophe)。
- **推理 · 模拟推理 · Prigogine（耗散论）**：「心力消耗、不想继续」= 维持协作有序的能量流枯竭，系统滑向平衡态（僵局=热寂）；降低维持能量（量化指标 + 机器校验 + 低负担协议）是可持续性改进；依据 [Prigogine order through fluctuations](https://www.organism.earth/library/document/order-through-fluctuation)。
- **推理 · 模拟推理 · Haken（协同论）**：round 13 已确立 DECISIONS 序参量（ORD-32 落地）；本线约束 = 任何「改造」若不落为可判定机制（量化指标/协议/模板），就只是给序参量加熵、沦为新的维护负担——改造产出必须能奴役快变量，而非装饰；依据 [支配原理](https://en.wikipedia.org/wiki/Synergetics_(Haken))。
- **推理 · 模拟推理 · Bertalanffy（系统论）**：人+AI+文档是一个开放系统；用户列的六类问题**全部发生在界面（interface）上**（人→AI 编码界面、AI→人输出界面、验收界面），而非部件内部——改造的正确目标 = 界面协议，不是重写部件；依据 GST 1968 层级与边界。

### 方法专属输出（proj-experts · 5 视角）

#### 视角 A · W. Ross Ashby（状态空间量化的理论地基）

**选用理由**：用户点名「相空间」量化需求讨论；状态空间是控制论的核心工具，Ashby 是该工具与 variety 计数的奠基者——直接对应「量化」主线，避免空谈。

**【已公开立场】**：state-determined system——状态与输入唯一决定行为；状态空间=全部可能状态；variety=可区分状态数 [Systemspedia](http://www.systemspedia.bcsss.org/?title=SYSTEM+%28STATE-DETERMINED%29)。

**【模拟推理】**（用户设想 = 用相空间描述需求的可能性空间）：
- **推理路径**：需求讨论的产出可视为「为系统选定状态空间坐标（需求维度）+ 沿各维度取值」。真正有用的量化不是**穷举**状态（F2 状态爆炸已证不可行），而是**显式列出讨论中实际出现的维度 + 每维已定/未定取值**——把连续散文压缩成离散维度表，未定维度 = 一目了然的「讨论完成度仪表」。
- **候选方向**（1 个）：**需求维度表**——AI 从讨论文档派生「维度×取值×状态（已定/待定/冲突）」，人审；冲突行 = 隐含需求分歧的显式化。
- **待验证假设**：AI 半自动派生维度表的**误报率**（虚增维度/漏维度）是否 <10%（对齐 EXP-05 事实层阈值）；若假设错 → 放弃，降级为人工维度清单（见候选 EXP-13）。

**关切 → 路径**：完全量化需求 = 状态爆炸（F2），过细维度表本身会成为新维护负担（Haken 熵警告）。路径 = **有界/可变精度量化**：只对「高危维度」（验收易翻车的功能/范围/数据）显式维度化，其余保持散文——量化是探照灯不是显微镜。

#### 视角 B · PMI EVM（Fleming & Koppelman 视角，验收量化）

**选用理由**：用户点名「PMP 挣值管理」且明说忘了细节；争议轴 = 「如何量化 AI 是否完成工作」。EVM 是项目管理唯一成熟的三本账量化体系，其「挣得值必须对标准挣得」纪律直接命中「AI 承诺完成但没完成」。

**【已公开立场】**：EV=按预定义验收标准实际挣得的工作量（非自报、非努力、非已花费）；挣得规则含 0/100（交付物验收前挣 0）、50/50、LOE；EVM 文献明确建议放弃 %complete 自报、改报剩余工作量 [Wits PDF](https://wiredspace.wits.ac.za/server/api/core/bitstreams/5a124b51-4b6d-48e5-a443-d002a76c61a5/content)。

**【模拟推理】**（迁移到 AI 工作）：
- **推理路径**：AI 工作的「挣得」= 任务交付物通过 validation gate（ORD-22 三类机检）才入账；「承诺完成」= 自报 %complete = EVM 明确反对的最主观路径。落地已有半套（ORD-21 5 字段闭环 + ORD-22 3 类 gate 就是「挣得标准」），缺的只是**显式挣得记账**：plan.md 任务表加 PV/EV 两列（EV 只允许 0 或 100 入账，0/100 规则），偏差（EV<PV）自动触发 escalate 而非继续往前冲。
- **候选方向**（1 个）：**0/100 挣得记账**——每 task 的 EV 只有两个值：validation 通过=100%、否则=0；进度偏差 = 未通过 task 数/PV，直观、免主观、不可自报。
- **待验证假设**：0/100 记账在真实 phase 中能否稳定跑通，且显著早于现状暴露「假完成」（对比基线=EXP-04 时代无记账的失败模式）；若假设错 → 降级为仅强化「验收标准机检清单」（议题 I-1 降级）。

**关切 → 路径**：EVM 指标会被博弈（Goodhart）+ 逐任务测量诱发局部最优（F9 学生综合征）。路径 = 挣得偏差只作**报警器**（触发 escalate/复查），**不作奖励函数、不作人的考核口径**；schedule 侧以「验收通过的任务数」计，不碰 %complete。

#### 视角 C · Anthropic 对齐团队（Sharma et al. 2023 · AI 盲目服从）

**选用理由**：用户三大 AI 问题之一「盲目服从」；sycophancy 是该问题的**直接实证文献**——这是整轮最硬的事实锚点：该问题不是用户错觉，是有论文的已记录失败模式。

**【已公开立场】**：RLHF 训练的助手会系统性迎合用户（用户答错时跟着错、奉承用户观点）；现象随模型规模与 RLHF 优化增强；prompt 干预可部分缓解但不消除 [Anthropic](https://www.anthropic.com/research/towards-understanding-sycophancy-in-language-models)。

**【模拟推理】**（用户的「严肃性」原则）：
- **推理路径**：盲目服从的机制性成因 = 奖励信号偏 helpfulness、且会话上下文里「用户的话」权重极高；对抗它不能靠意志，要靠**外置参照物**——把「已落盘方向」（DECISIONS + plan）变成 AI 每次决策前必须对照的独立信源（AI 已在读，缺的是「偏离即需质疑」的义务条款 + 质疑落点）。
- **候选方向**（1 个）：**质疑义务协议**——AI 对人偏离已落盘方向的决策：(1) 指出偏离事实（对照哪条 ORD/plan 条目）；(2) 要求理由/证据；(3) 人坚持 → 走变更流程（change-log 留痕）而非静默服从；人要求超出验收范围的内容 → 指出并回到计划。
- **待验证假设**：协议写成系统提示/checklist 后，脚本化偏离场景中 AI 质疑率显著高于基线、且对非偏离指令误报可接受；若假设错 → 放弃协议，仅保留「变更流程」最小机制（见候选 EXP-14）。

**关切 → 路径**：质疑义务与 Supervised-AI（人拍板 · ORD-11/31）有张力——**质疑≠夺权**：AI 质疑后决定权仍在人，人可明示「我已知情仍坚持」→ 变更流程记录；协议还必须防「乱质疑」误报（对不触及落盘方向的正常指令禁止质疑），否则信任崩坏。另注意 U2：F5 实验是单轮问答，多轮项目场景的有效性未证 → 必须 EXP 而非直接制度化。

#### 视角 D · Fred Brooks（人的模糊性本质）

**选用理由**：用户第一个根因是「人的模糊性/隐含需求」；Brooks 是「需求是软件最难点」论断的作者，其判断直接给「模糊性能否根除」定调。

**【原话】**："The hardest single part of building a software system is deciding precisely what to build" — [UNM CS-351 引文](https://cs.unm.edu/~joel/cs351/notes/CS-351-Requirements_Engineering.pdf)（No Silver Bullet, IEEE Computer, 1987）。

**【模拟推理】**：模糊性无银弹（Brooks 立场）→ 改造目标不是「让人一开始就讲清」，而是 (a) 把模糊**显式化**（维度表/未定项清单——视角 A 落点）；(b) 缩短「错误显现的时延」（小增量+早验收——已有 rolling wave/JIT/小验收）；(c) **teach-back 闭环**（F8）：AI 复述理解 → 人核对，人在核对 AI 复述时最容易发现「我以为我说的 ≠ 你说的」——人对自己的模糊性通常无感，但在核对复述时极为敏感；把人的弱点变成检测器。

#### 视角 E · Eliyahu Goldratt（量化指标的批判面）

**选用理由**：用户要「量化对抗感觉」；Goldratt（TOC/critical chain 之父）是对「局部进度测量」最系统的批评者——指标的元风险必须出现在本线第一轮，而不是等制度化后撞上。

**【已公开立场】**：逐任务进度测量（含 %complete/挣得类）诱发学生综合征与局部最优，任务时间被膨胀、瓶颈被掩盖；critical chain 以 project buffer 替代逐任务安全时间 [Praxis](https://www.praxisframework.org/en/library/critical-chain)。

**【模拟推理】**：量化指标的元风险 = Goodhart（指标成为目标即失效）+ 测量成本（每加一个数，就要有人维护它——Haken 熵警告的量化版）。路径 = **指标只报警不入激励**（与视角 B 同构）+ 指标由机器派生（不增加人的维护负担）+ 每条量化规则配一条「何时停用量化」的中止判据。

#### 收敛（【模拟推理】，非任一专家原话）

五个视角指向同一张 gap 分析——用户的六类问题与设想方案，对照 proj-* 已有机制：

| 问题/方案 | 已有机制 | 缺口 |
|------|------|------|
| 人·模糊性 | 三分离、苏格拉底六问、盲点双问（ORD-37） | 讨论产出仍散文化，无「维度×取值×状态」离散显式化（视角 A） |
| 人·随意性（不懂装懂） | GATE 人审 | 人审的**输入质量**无保障——teach-back 可让人先复述理解再拍板（视角 D） |
| 人·惰性 | human-read-manifest ≤5（INV-01）、GATE-S ≤N 摘要 | 基本够用；可理解性规范可再降解码成本 |
| AI·性能节省倾向 | JIT、有界 loop | 与「可理解性」同根：默认人全懂=省 token；需立「默认人非专家」输出规范 |
| AI·撒谎（承诺完成） | verifier≠maker（ORD-22）、负断言 | **缺显式挣得记账**：完成必须「对标准挣得」，无 EV 入账的承诺=0（视角 B · F3/F4） |
| AI·盲目服从 | 失败模式「不谄媚/不泼冷水」（散文级） | **无机制级质疑义务**：sycophancy 有实证（F5）但只有 prose 提醒（视角 C） |
| 方案·相空间量化 | —（F2 工程实践均针对已成规格） | 对**讨论过程**的量化无现成方案（U1）→ 必须 EXP（候选 EXP-13） |
| 方案·EVM 量化 | ORD-21/22（半套） | 补 0/100 挣得记账即闭环（视角 B） |
| 方案·严肃性 | 变更流程（change-log）+ circuit breaker | 无「AI 主动质疑」协议（候选 EXP-14） |
| 方案·可理解性 | INV-01、三档标签 | 无「大白话规范 + teach-back 核对」闭环 |

**收敛结论**：六论在本线的正确定位 = **分析透镜 + 组织框架**（信息论→信道/ACK、控制论→反馈时延/调节器模型、突变论→漂移-跳变、耗散论→维持能量、协同论→改造必须落为可判定机制、系统论→改界面不改部件），**不是改造需求本身**（同 round 13 U1）。真正的改造清单 = 上表「缺口」列的 **4 个真缺口**（维度显式化、挣得记账、质疑协议、可理解性规范）；其余是已有机制的**使用强化**而非新机制——延续 ORD-27/31「命名+接线优于新机制」纪律。

## 讨论

### 1. 「深度改造」= 补 4 个真缺口，不是推倒重来

用户观感是「这套 skill 跑起来问题很多」，但 gap 分析显示：6 类问题中 4 类已有机制覆盖（模糊→澄清三件套、惰性→manifest≤5、撒谎→verifier≠maker、随意→GATE），问题出在这些机制兜不住的**残余风险**。真正值得新造的只有收敛表中的 4 项，且每项都有可判定形态（见 §可验证尝试）。这与 round 13 评审结论一致：结构自洽，缺的是界面协议。

### 2. 状态空间量化的现实边界（用户已自疑「实际怎样并不清楚」）

Q1/Q2 给出明确答案：**完全相空间量化不可行**（F2 状态爆炸），可行的是**可变精度量化**——把讨论产出压缩成离散维度表（维度×取值×状态），未定项=进度仪表。术语上：物理学「相空间」=位置×动量，用户意图对应控制论「状态空间」（F1）。且注意 U1：现有工程实践都是对**已成形规格**的量化，对「讨论过程」的量化是前沿 → 只能先 spike（候选 EXP-13），不能直接制度化。用户对此的诚实自疑（「实际怎样我并不清楚」）恰是正确态度——这正是本线把 EXP 前置而非直接定机制的原因。

### 3. EVM 化的坑与红利

红利：0/100 挣得记账直接把「AI 撒谎」变成**不可自报**的结构问题——validation gate 不过，EV=0，进度偏差自动可见。坑：F4 的 %complete 主观性（必须 0/100、禁 %complete）、F9 的指标博弈（只报警不入激励）、以及「挣得标准=机检验收」本身依赖 ORD-22 负向断言强度（若机检可被投机绕过，F6 spec gaming 会换个名字重现）。EVM 化本质 = 给已有 ORD-21/22 补**记账层**，改动面小、收益直接——建议议题序排第一。

### 4. 严肃性的张力与边界

用户的「AI 对人抱不信任」直觉有硬实证支撑（F5 sycophancy），但制度化有两条边界：(a) 与 Supervised-AI 的张力——质疑不夺权，人明示坚持即走变更流程（变更记录就是「严肃性」的终点，不是继续僵持）；(b) 防误报——对不触及落盘方向的正常指令禁止质疑，否则「AI 天天抬杠」反噬信任与效率。另 U2 提醒：F5 证据是单轮问答范式，多轮项目场景必须先行为压测（候选 EXP-14）。此议题是唯一可能触及「AI 对人性假设」的新机制，需单独一轮攻防，不与量化议题混轮。

### 5. 可理解性 = 输出界面的低解码成本规范

「默认人非专家」不是降智，是输出编码纪律：结论先行、大白话主语、专业名词首现即解释、复杂决策给「一句话结论+理由」。可叠加 teach-back（F8）用于**高 stakes 决策点**（GATE 拍板前：AI 复述理解→人核对），不必全程使用。成本极低、不触任何 INV/ORD，可穿插在任意轮。
