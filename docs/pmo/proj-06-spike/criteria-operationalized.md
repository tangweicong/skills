# EXP-06 · 分支判据算子化（被测物硬化）

> 把 proj-survey §分支判据的 provisional **定性 4 维（高/低）** 变成**可操作算子**：每维「可观测信号 → 0/1/2 打分」+ 组合规则 → 分支建议。EXP-06 假设 =「存在可操作的 GATE 判据」，本文件即对该假设的构造性回答。

## 4 维 · 可观测信号 + 打分（0=低 / 1=中 / 2=高）

| 维度 | 0（低）| 1（中）| 2（高）| 可观测信号（proj-survey 半机判）|
|------|--------|--------|--------|------------------------------|
| **D1 来源丰富度** | 仅零散代码，无测试无 doc | 代码 + (README 或 测试) 之一 | 测试 + 代码 + doc 多源印证 | 有测试目录且可跑? README 非空? git 有 issue/PR 引用? 命中源种类数 0–1→0 / 2→1 / ≥3→2 |
| **D2 来源新鲜度** | docs/代码明显陈旧或漂移严重 | 部分新鲜部分陈旧 | 近期活跃且 doc↔代码一致 | git 最近提交距今? README 提及的入口/命令在代码里还在? 漂移项占比 |
| **D3 未完成工作可识别度** | 说不清还差什么 | 部分可定位 | 明确（TODO/issue/缺失 stub 可定位）| TODO/FIXME 数 + issue 未决 + 未实现 stub 是否能列举 |
| **D4 矛盾程度（高分=矛盾少）** | doc↔代码↔测试方向性互相矛盾 | 局部不一致 | 无方向性冲突 | 测试断言 vs README 声称 vs 代码实现是否冲突 |

> D4 反向命名：分高 = 矛盾**少**（与 D1–D3「高=好」对齐，便于求和）。

## 组合规则（算子 → 分支建议）

```text
输入：D1,D2,D3,D4 ∈ {0,1,2}；total = D1+D2+D3+D4（0–8）
R1 任一维 == 0           → 建议 AUDIT（硬规则，对齐 provisional「任一低→audit」）
R2 全维 ≥ 1 且 total ≥ 6 → 建议 PLAN
R3 其余（全≥1 但 total<6）→ 建议 GATE-S 人审，默认 AUDIT（= EXP-06 中止路径 B 保守兜底）
```

**设计依据**：
- R1 保「任一低→倾向 audit」的原始纪律不丢。
- R3 把「中间模糊带」显式交 GATE-S + 保守默认 audit（S-2 无 oracle 不证完整 → 宁可保守）。
- 阈值 6/8 = 「至多一维为中(1)、其余高(2)」才直接 plan；更弱即落人审。**阈值本身是可调超参，EXP-06 难例压测用于校准**。

## 与 provisional 判据的关系
- 不改 4 维语义，只**补可观测信号 + 打分 + 组合规则** → 从「定性倾向」升为「可复现算子」。
- GATE-S（S-1）与中止路径 B 不变：算子只产出**建议**，分支仍经人审批。
