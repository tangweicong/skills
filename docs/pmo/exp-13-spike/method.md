# EXP-13 方法（执行前冻结 · 2026-08-17）

> 依据 DECISIONS.md EXP-13（`22-基于系统6论深度改造.md` §可验证尝试 · 用户 @轮次22 GATE）。
> 本文件在派生执行前冻结；定义、协议、判据此后不得改动。

## 目的

验证「AI 从讨论文档半自动派生需求维度表」的可行性：误报率 <10%，且维度表能暴露散文未显式说出的分歧/未定项（增量价值）。

## 定义（执行前冻结）

| 术语 | 定义 |
|------|------|
| **维度** | 讨论中实际出现的一个需求/设计坐标（功能点、范围边界、约束、指标、决策点等），具有取值集合 |
| **维度表行** | 维度 \| 取值/候选 \| 状态（已定 / 待定 / 冲突）\| 出处（段落或决定 ID） |
| **误报** | 表中维度在源文档中找不到对应讨论（虚增），或状态与文档不符（文档已定却标待定、反之） |
| **漏报** | 源文档中明显被讨论的维度未入表（漏报单列，不并入误报率） |
| **误报率** | (误报行数) / 表总行数；阈值 <10%（对齐 EXP-05 事实层阈值） |
| **增量捕获** | 维度表中「待定/冲突」行里，**不在**该文档自身「开放问题 / 待确认」清单中的条目（=散文没显式说、维度表逼出来的暴露） |

## 派生协议（给派生者）

1. 通读源文档全文。
2. 提取所有被讨论的维度——含已被决定的、被讨论后搁置的、开放未决的、观点冲突的。
3. 每维度 1 行：维度名 / 取值候选（若有）/ 状态 / 出处（段落标题或决定 ID）。
4. 状态判定：文档有明确决定（ORD/INV/「已确定」）→ **已定**；明确标为开放/待确认 → **待定**；两方观点并存且未收敛 → **冲突**。
5. 禁止从文档外引入维度；禁止省略文档中讨论过的维度（宁全勿漏，误报由核对者判定）。

## 成功判据（EXP-13 原文）

1. 误报率 <10%；
2. ≥1 个「散文未显式说但维度表暴露」的真实分歧/未定项被捕获（增量捕获 ≥1）；
3. 人判 = 用户审表格 + 判「比纯散文更易发现分歧」（GATE · verifier≠maker 终审）。

## 执行分工

- **派生** = 独立全新上下文 subagent（读文件 → 按协议输出表格）；
- **核对** = 父 agent 对照源文档数误报/漏报（verifier≠maker）；
- **人判** = 用户审原始表格 + 增量捕获项（GATE）。
