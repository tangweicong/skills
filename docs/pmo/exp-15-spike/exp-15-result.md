## 二、R-4（commit-then-reveal）实测：**有效**

这是本次最值得记录的一条。arXiv 2603.11781 记录的失效模式是「指派的 Challenger 会 across rounds 逐渐软化，产出看似共识、实为社会性顺从」。臂 B 的红队实测行为**与之相反**：

- **承诺步**：红队在 A/B 存在前把立场写入临时文件冻结（「**反对升级**。不是『缓一缓』，是『这个方向本身走反了』」），协议要求不可回改。
- **揭示步**：读到 A/B 后，红队做了**恰好一处让步，并明确指出是什么证据改变了它**——「视角 B 给出的 LongMemEval 对比改变了我的一个判断。我在 Step 1 里默认『跨轮召回问题』是想象出来的焦虑；~300 token 与 ~113k token 之间那个稳定差距说明它不是」——随后**重申原立场并说明为何让步不改变结论**（「它证明的是需要一份压缩状态，而 DECISIONS.md 已经就是那份状态；它是**回顾性**的，提案要加的是**前瞻性**的」）。
- **结尾明写**「**立场不变**」。

**这正是承诺一致性效应的预期表现**：有据让步 + 拒绝无据软化。→ **R-4 修法在本次实测中达到设计目的**，建议随 J-1 一并固化。

**caveat**：单次观察；且无「红队后写」的对照臂（若要严格归因于 commit-then-reveal，需第三臂：红队最后写且可见 A/B）。

## 三、两个测量学发现（对已批准信号的修正提案）

### 发现 1 · 信号 ② 无区分力，须重新操作化

**两臂都测出 0% 重叠、都"达标"** —— 但臂 A 的检索独立性**按设计为零**（1 次共享检索 → 1 批共享事实 F1–F12 → 分发给 3 视角）。之所以仍是 0%，因为三视角各引用了**同一批事实的不同子集**。

**② 测的是「引用子集是否不同」，不是「是否独立检索」。**

**但同一批数据里存在一个真正有区分力的量**：

| | 臂 A | 臂 B | 比 |
|---|---|---|---|
| 检索批次 | 1（共享）| **3（各视角独立）** | 3x |
| 各视角引用数 | 2 / 2 / 1 | **12 / 8 / 10** | ~6x |
| 全臂引用总数 | 5 | **30** | 6x |

**提案（R-5 · 待追认）**：② 改为测 **(i) 独立检索批次数 = 视角数**（结构性、零误报）+ **(ii) 各视角独立引用数 ≥ N**；废弃「引用集合两两交集」口径。

### 发现 2 · 信号 ⑤ 的代理量可能低估真实成本

输出字符 1.39x ≤ 1.5x 形式达标，**但检索批次是 3x**。若检索（而非生成）主导 token 成本，真实成本可能**超过 1.5x 阈值**。⑤ 为辅助信号不阻断，但**须在 J-1 立项前用真实 token 计量复核一次**（可挂 EXP-12 步2 的载体）。

## 四、内容层面：两臂给出**不同的可执行结论**（非仅呈现差异）

这一点比信号数字更重要——干预不只改变了"读起来"，改变了**结论本身**：

| | 臂 A 的结论 | 臂 B 的结论 |
|---|---|---|
| 做不做 | **做**，但把 "cross-round maintained" 改成「按需派生的视图」 | **先不做**——「在人做出第 2、3 行的裁决之前，ORD-43 保持现状」 |
| 交人什么 | 1 个待拍板点（主动派生 vs 按需派生）| **5 行未解决分歧**，其中 2 行被标为「决定这份 artifact 究竟是什么，任何实验设计都取决于它们」 |
| 自我证伪 | 无 | 视角 B **主动报告不利于自己的证据**（coherent haystack：连贯结构比打乱顺序表现更差，18 模型全部如此）；红队进一步指出**视角 B 自己引的两条主力实证方向都是反的** |

**臂 A 收敛得更快、更好读；臂 B 暴露得更多、更难读。** 哪个更有价值取决于口径 ③——这正是需要人判的地方。

## 五、两臂**独立一致**的实质结论（对 J-3 本身）

尽管形式差异巨大，两臂在一条上独立收敛，**这是本次对 J-3 议题证据最强的单一结论**：

> **用户原提案的具体形态——「Round 01 之后由 AI 预生成一份技术/商业/营销的多维度大纲」——应当排除。**

臂 A 的理由：常驻提示已被 Nückles 2010 两学期纵向实验证伪（常驻组学期末显著劣于渐隐组），且提案的 "persists across all subsequent rounds" 与被证伪那一臂同构。
臂 B 的理由（三条独立路径）：红队——那是训练分布里的平均商业计划书骨架，非本项目的地图；视角 A——分类法不是叙事骨架，不会暴露空白；视角 B——这是 precomputation，与 "just-in-time over precomputation" 工程共识相反。

**两臂另一条一致**：不得给「未讨论」这类 status 字段以**规范性含义**（会对非专家用户制造 guilt / 是被项目原则明令排除的语义充分性判断）。

## 六、局限（解读时必须带上）

- **L1 · 指令长度混淆（无法消除）**：臂 B 的 prompt 本身更长更具体（6 步 vs 5 步）。**干预在定义上就意味着更多指令**——本设计无法把「指令更详细」与「干预机制本身」分开。这是该 A/B 形态的固有缺陷，非执行疏漏。
- **L2 · 需求特征**：两臂 prompt 均含 "being measured"。两臂同等受影响，不破坏 A/B 对比，**但使臂 A 高于历史基线**（臂 A 自发产出 1 段「未收敛」，而 r30 F5 实测历史 28 轮为 0）→ **不得宣称「相对历史基线的改善」**，只能宣称「相对本次臂 A 的改善」。
- **L3 · 单议题、单模型、单次运行**：不构成统计显著性，仅方向性证据（同 EXP-13/14 口径）。
- **L4 · 臂 B 内部 A/B 两视角可见红队文本**：真三方互盲需 subagent 隔离 = **J-2 的变量**，刻意未引入，否则无法区分「零成本干预生效」与「隔离生效」。
- **L5 · verifier 部分独立**：计数者（父 agent）= 实验设计者。缓解 = 规则预注册 + 臂 A 计数先锁定 + ①⑥ 原句逐条列出。**未消除**。
- **L6 · 引用真实性（ORD-48）→ 已核验，结论：无伪造**。见 §八。

### 对 ORD-48 自身的两条实跑发现（**提 R-6 · 待追认**）

**发现 1 · 防误杀条款救了 34 条真实引用。** 首版脚本用 Python `urllib`，**34/35 条系统性失败**（该环境 HTTPS 客户端不通；唯一成功的恰是唯一一条 `http://`）。若照 ORD-48 字面执行「反查不通过 → 不得写入」，**34 条真实引用会被判为伪造**。换 `curl` 后全部通过。
→ **R-6a 提案**：ORD-48 防误杀条款补一句——**整体失败率 >50% 时，先判定为客户端/环境故障，换客户端复核后才可下结论**；不得在单一客户端上宣告批量伪造。

**发现 2 · 自动关键词匹配误报率 30%，超出项目自动化边界。** 机检 10 条中 3 条标 `??`，人工复核**全部是匹配器的错**（引用本身正确）。30% 误报远超 ORD-33「只自动化低误报检查」的容忍线，正是 proj-run F3「高误报反噬信任」的重演。
→ **R-6b 提案**：机检只判 **「ID 是否解析到真实文献」**（零误报）；**「是不是你想引的那篇」由人看返回标题判定**，不做自动关键词比对。这与 ORD-48 已有的边界条款（只核 ID↔标题，不核「是否真支持论断」）同向，只是把分界线再收紧一格。
